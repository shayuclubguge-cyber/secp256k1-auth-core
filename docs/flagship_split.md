# 旗舰核拆分设计 v1（2026-08-18）

目标：把 73,653 门的 ecrecover_core 拆成 **≤255 引脚、单件 <1 万门** 的 REF 零件，
在链上组合成完整的 ECRECOVER Auth Core。

## 硬约束（全部实测）

| 约束 | 数值 | 来源 |
|---|---|---|
| REF 引脚上限 | ≤255 入 / ≤255 出 | 协议 |
| OKX 钱包发送上限 | ~30M gas ≈ 1 万门 | 实测（加法器 49M 被拒） |
| BSC 区块上限 | 55M gas ≈ 1.8 万门 | 实测 |
| REF 成本 | 零（不烧任何代币） | cid5/cid6 实测 |
| 跨处理器 REF | 允许 | cid6 实测 |

## 核心架构决策：字串行（word-serial）数据通路

组合式 256 位运算需要 512+ 输入引脚，超 REF 上限 → **必须字串行**：
操作数按 64 位字分 4 拍流入/流出，零件引脚 ~70 入 ~66 出（与老橘子流式风格一致）。

## 有状态 REF 探针结果（cid7/cid8，2026-08-18）

- **✓ 状态穿透成立**：cid8 的 circuitInfo nState=8，子电路 LATCH 计入父电路状态向量
- **✗ 但 step() 裸调用发现两个怪癖**：输入不进 LATCH 采样（探针A实测）、非零 state 字节空 revert（疑似防伪造）
- **结论**：时序电路的驱动路径改为**见证合约 beat()**（部署一次，持久状态 + 留痕），而非裸 step
- 零件仍按「自带寄存器」设计（穿透成立），驱动层走 beat

## 零件清单（两分支通用部分）

| 零件 | 引脚(入→出) | 门数估 | 功能 |
|---|---|---|---|
| fadd64 | ~70→66 | ~2.5k | mod-p 加/减：4 拍送字 + 4 拍读回，进位/借位跨拍保持 |
| fmul_ws | ~70→66 | ~4k | mod-p 乘：字串行移位-加，~1,030 拍/次 |
| regfile | ~75→66 | ~1.3k 门 + 2k LATCH | 4×256 位寄存器堆，字端口读写 |
| ctrl_fsm | ~30→40 | ~1.5k | 点运算微序列（Jacobian 倍点 8 乘 / 加点 16 乘的调用序） |
| keccak_link | REF cid4 | 0 | 地址派生（复用已验证组件） |

## 顶层：ecrecover_auth（≤255 引脚，目标 <1.2 万门）

引脚协议（全部字串行）：
- LOAD：12 拍载入 z/r/s/v（96 字节）
- RUN：1 拍启动 → 内部约 2.6 万拍（2 次标量乘 + 1 次模逆 + 1 次开方 + 收尾）
- READ：5 拍流出 20 字节地址 + valid 标志

驱动方式：链下驱动器用免费 view `step()` 串状态跑完 2.6 万拍，
只有需要持久化结果时才发 beat 交易（每次 beat 仅 ~7 万 gas）。

## 预算总览

| 阶段 | 拍数 | 说明 |
|---|---|---|
| lift_x（开方） | ~8,200 | 费马 (p+1)/4，32 次乘 |
| sR 标量乘 | ~13,100 | 256 轮 × (倍点 8 + 加点 16)/2 均摊 |
| zG 标量乘 | ~13,100 | 可与 sR 复用数据通路 |
| r⁻¹ mod n | ~2,000 | 二进制 XGCD（sub + 比较，用 fadd64 实现） |
| 收尾（仿射化+keccak） | ~1,000 | 1 次模逆 + keccak |
| **合计** | **~3.7 万拍** | 全程免费 view 调用可跑完 |
