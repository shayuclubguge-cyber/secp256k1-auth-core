## 三、功能验证：Keccak-256 链上测试

**先说任务书本身的两个问题：**

1. 任务书给的「标准 Keccak-256("abc") = 0x3a985071…e8e8」**是错的**。正确值为
   `0x4e03657aea45a94fc7d47ba826c8d667c0d1e6e33a64a036ec44f58fa12d6c45`（本审计脚本自带 Keccak 实现，已对空串/abc/name() selector 三向量自检）。空串值 0xc5d24601… 是对的。
2. 「输入 abc 直接读回哈希」的测法**不适用于 cid7**：cid7 是 204 入 64 出的**流式计算组件**（θD/XOR3/χ 三模式），不是哈希预言机；完整 Keccak-256 需要主控电路逐拍驱动约 2,400+ 拍。

**但功能本身可以独立复现，且已复现成功：**
通过见证合约（0xA2dE…7DCf）的 `evaluate(address,uint256,bytes)`（selector 0x136ade26，本审计自行计算），LSB-first 位打包，实测：

- XOR3 模式随机向量 3 组：链上输出 == a⊕b⊕c ✅✅✅
- χ 模式随机向量 1 组：链上输出 == a⊕(¬b∧c) ✅

**4/4 链上实时复现通过。** 电路在链上确实在做它声称的计算。

2. **功能**：13 颗电路注册与字节指纹 13/13 可复现；cid7 计算功能 4/4 链上实时复现。
